# Harness 上下文

这个上下文描述本仓库里用于长时运行 coding agent 工作流的核心语言。它只是一份术语表，用来帮助用户和 agent 在讨论状态、验证、证据和交接时使用同一套词。

## 术语

**长时运行 coding agent 工作流**：围绕同一个仓库连续推进多轮工作的协作方式，每轮结束后都要让下一轮能从仓库内文件无猜测地继续。
_避免_: 临时对话、一次性脚本任务、随手改代码

**Harness**：支撑长时工作流的一组仓库内工件，负责保存规则、功能状态、验证入口、进度和交接信息。
_避免_: 文档模板包、脚手架、辅助说明

**开工流程**：每轮开始时必须完成的状态读取和基础验证步骤，用来确认当前工作不是建立在坏的起点上。
_避免_: 准备工作、启动前检查、预检

**标准启动路径**：下一轮 agent 可以按同一方式重新进入项目的命令或步骤。
_避免_: 启动方式、运行方法、拉起命令

**标准验证路径**：判断仓库基础状态是否仍可继续工作的默认验证命令或步骤。
_避免_: 测试命令、检查命令、验收命令

**功能清单**：记录功能优先级、状态、验证步骤和证据的机器可读事实来源。
_避免_: todo、需求列表、任务池

**单一进行中功能**：同一时间只允许一个功能处于正在推进状态的工作约束。
_避免_: 当前任务、多任务并行、顺手一起做

**最高优先级未完成功能**：功能清单里优先级最高且尚未达到 passing 的下一项产品行为。
_避免_: 下一个想做的事、当前目标、待办第一项

**Passing**：目标行为已经实现，要求的验证已经真实跑过，并且证据已经写回仓库。
_避免_: 完成、看起来好了、代码已写

**证据**：能让后续会话判断验证确实发生过的记录，通常包含日期、命令、结果和关键观察。
_避免_: 备注、感觉、口头确认

**Blocker**：阻止当前功能继续推进的已知问题，需要被明确记录，不能靠猜测绕过。
_避免_: 风险、麻烦、待确认事项

**进度日志**：面向下一轮会话的连续记录，说明当前已验证状态、本轮动作、证据、风险和下一步。
_避免_: 工作日志、聊天摘要、提交说明

**交接摘要**：长会话或复杂变更结束时留下的短报告，帮助下一轮快速恢复上下文。
_避免_: 复盘、总结、备忘录

**质量快照**：对产品领域和架构层的当前质量评级，用来观察代码库是否随时间变强或变弱。
_避免_: 质量报告、评分表、健康度

**完成定义**：判断一个功能能否从未完成状态切换到 passing 的共同标准。
_避免_: 验收标准、完成条件、done
